# SCARA Robot Viewer

A Qt Quick 3D application that renders a 3-DOF SCARA-type robot arm with an orbiting camera. The arm has a PRR kinematic structure: one prismatic joint (vertical) followed by two revolute joints.

## Status

The viewer renders the static model. Joint motion, kinematics, drawing and speed plots are the next steps (see Roadmap).

## Robot

| Joint | Type | Motion |
|---|---|---|
| 1 | Prismatic (P) | Vertical travel along the column |
| 2 | Revolute (R) | Rotation of Link2 about a vertical axis |
| 3 | Revolute (R) | Rotation of Link3 about a vertical axis |

The two revolute axes are parallel, so joints 2 and 3 position the end effector in a horizontal plane and joint 1 sets its height. This layout suits planar tasks such as drawing.

The original CAD model is titled "Four Axis Robotic Arm". This project treats it as a 3-DOF arm and does not model tool rotation.

## Requirements

- Qt 6.10 or newer with the Qt Quick and Qt Quick 3D modules (developed with Qt 6.11.1, MinGW 64-bit, on Windows)
- CMake 3.16 or newer

## Build and run

With Qt Creator: open `CMakeLists.txt`, select a Qt 6.10+ kit, and run.

From the command line:

```
cmake -S . -B build -DCMAKE_PREFIX_PATH=<path to your Qt kit>
cmake --build build
```

Controls: drag with the mouse to orbit, scroll to zoom.

## Project structure

| Path | Purpose |
|---|---|
| `main.cpp` | Application entry point |
| `Main.qml` | Window, scene, lights and orbit camera |
| `Scara.qml` | Robot scene graph generated by Balsam, with hand-edited colors and mesh paths |
| `Resources/meshes/` | `.mesh` files loaded at runtime |
| `assets/source/` | Cleaned glTF source (not bundled in the executable) |

## Asset pipeline

```
STEP (CAD) → glTF (Open CASCADE) → merged in Blender → Balsam → QML + .mesh
```

1. **CAD export.** The original glTF was produced by Open CASCADE from a STEP file. It has one primitive per CAD face (about 23,000 for four parts: Base, Link1, Link2, Link3), all with a single shared material.
2. **Cleanup in Blender.** Importing and re-exporting the glTF merges each part into one mesh with one primitive and gives each part its own material. Object names are kept, because Balsam uses them for QML ids and mesh file names. Export settings: glTF Separate, +Y Up, compression off, animation off.
3. **Balsam.** Generates `Scara.qml` and one `.mesh` file per part:
   ```
   balsam --outputPath out Scara.gltf
   ```
4. **Integration.** The `.mesh` files go in `Resources/meshes/` and are listed in `RESOURCES` in `CMakeLists.txt`. In the generated `Scara.qml`, each `source:` path gets the `qrc:/qt/qml/Scara/Resources/meshes/` prefix, and the material colors are adjusted by hand.

Without the merge step, the generated `Scara.qml` would have about 23,000 lines (one node per CAD face). After it, the file has about 90. The mesh data itself (about 277k triangles) is unchanged.

To change the model, edit the glTF in Blender, re-export, and re-run Balsam. Balsam overwrites the `source:` prefix and the material colors, so re-apply them.
